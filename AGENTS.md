# AI-Generated Code Policy

Any code changes made by AI agents must include a model signature for traceability and reproducibility.

## Signature Requirements

### Commit Messages
Include the model identifier in the commit trailer:

```
Co-authored-by: <Model Name> <model_id>
```

**Example:**
```
Fix database connection pool timeout

- Increase pool size from 5 to 10
- Add retry logic on connection failure

Co-authored-by: Claude Sonnet 5 (claude-sonnet-5)
```

### Complex Code Sections
For substantial AI-generated logic blocks (algorithms, business logic, integration code), add a brief comment:

```java
// Generated by Claude Sonnet 5 (claude-sonnet-5)
// Purpose: Service configuration binding and validation
public EnumMap<Services, AbstractServiceConfig> toRuntimeConfigs() {
    // implementation...
}
```

### Pull Requests
Include model information in PR description:

```markdown
## AI Assistance
Generated with: Claude Sonnet 5 (claude-sonnet-5)
Changes: Test refactoring, fixture setup
```

## Why

- **Reproducibility**: Trace decisions back to which model generated them for future improvements
- **Accountability**: Clear record of AI involvement in critical sections
- **Debugging**: Helps identify patterns in model-generated code if issues arise
- **Governance**: Transparent tracking of AI contribution to codebase

If a signature is not present on a commit that even *appears* to be generated by an LLM, the PR will be closed.

## Model ID Format

Use the exact model identifier provided by the AI system, e.g.:
- `claude-sonnet-5`
- `gpt-5.6-sol`
- `gemini-3.8-flash`
